# Connect Shopify observations to Mango

This is the maintained producer for Mango's existing Worker and D1 database. It does not require a second Worker, project or external relay. Do not install or release it without the shop owner's authorization. Local tests prove the software boundary; they do not establish a live installation.

Use a Shopify app with **custom distribution restricted to this one shop** and credentials exclusive to that shop. The app client secret is the webhook/app-proxy secret. A shared multi-shop app secret is unsupported: Shopify's raw-body webhook HMAC does not sign the shop/topic headers. `COMMERCE_EXCLUSIVE_SHOP` is the owner's assertion of the actual single-shop credential boundary, not cryptographic verification that a shared app became single-shop. Do not set it for shared credentials. Use the canonical `example.myshopify.com` host in both that input and `COMMERCE_STORE_URL` (HTTPS). Keep `COMMERCE_API_TOKEN` and `COMMERCE_WEBHOOK_SECRET` server-only.

In that app's Shopify CLI project, include this directory under `extensions/mango-pixel`. Install its package through the app project's normal dependency workflow, generate its extension identity through Shopify CLI, and deploy the extension through the authorized app release workflow. No real app IDs or credentials are shipped here.

The app requires `read_customers`, `read_products`, `read_inventory`, `read_locations`, `read_orders`, `read_all_orders` (approved access to older orders), `read_returns`, `read_pixels`, `write_pixels`, `read_customer_events` and `write_app_proxy`. Grant required protected customer data access for customer email, phone, names and location used by Admin imports. The pixel does not request or transmit customer name, address, email, phone, client ID or browser-supplied customer ID. Missing scopes, denied protected fields, GraphQL errors and malformed responses fail the source visibly. Shopify's supported API-2026-07 customer consent fields are retained independently; they never subscribe a Mango channel.

Configure the app proxy in the existing app's `shopify.app.toml`:

```toml
[app_proxy]
url = "https://YOUR-MANGO-ORIGIN/webhooks/commerce/shopify/observations"
prefix = "apps"
subpath = "mango-signals"
```

Create **shop-scoped** subscriptions using Admin `webhookSubscriptionCreate`, without filters or include-field restrictions, JSON format and app webhook API version 2026-07. The health query intentionally checks API-created shop-scoped subscriptions; Shopify does not expose TOML app-scoped subscriptions through that query. Deliver subscriptions to `/webhooks/commerce/shopify` on your Mango deployment's HTTPS origin.

Configure exact webhook topics `carts/create`, `carts/update`. Other supported notifications are `customers/create`, `customers/update`, `products/create`, `products/update`, `inventory_levels/update`, `inventory_items/update`, `orders/create`, `orders/updated`, `orders/paid`, `orders/cancelled`, `refunds/create`. Subscribe only those topics you intend to use. Cart subscriptions require `read_orders` and cover Online Store carts, not custom storefront carts. Customer/product/order notifications reconcile through Admin GraphQL so incomplete webhook payloads cannot overwrite complete records. Nested line, return, refund-line and inventory-level connections are fully paged before a source page is accepted.

Release the strict sandbox extension with explicit analytics and marketing purposes. The shipped sale-of-data policy is conservatively `enabled`, so sale-of-data opt-out stops collection too; CONT-018 requires sale-of-data permission, so the declaration stays `enabled`; changing it is a contract change, not an install choice. Activate it with `webPixelCreate(webPixel: {settings: JSON-string})`, providing settings `{"channel":"YOUR-UNIQUE-INSTALLATION-CHANNEL","proxyPath":"/apps/mango-signals"}`. This needs `write_pixels`, `read_customer_events`, permission and a released extension. Set `COMMERCE_OBSERVATION_CHANNEL`, `COMMERCE_APP_INSTALLATION_ID`, `COMMERCE_PIXEL_ID` and `COMMERCE_PROXY_PATH` on the same Mango deployment to the actual installation/pixel IDs and settings. A new installation requires a new channel identity.

Sync customers, products and variants before qualifying observations. Sync any source to run the actual Admin installation/scopes/pixel-settings/cart-subscription check. The native authenticated `GET /api/store/observations?sourceType=cart` (or `browsing-event`) reads the bounded log; pass its opaque `nextCursor` for the next page. Store shows last successful refresh, channel check, retention and last observation separately. A healthy quiet log can complete an explicitly pinned zero-event range. Sync runs read a fixed durable high watermark; retention or privacy deletion invalidates old cursors. Observations are retained for 30 days; receipts retain only digests/IDs. Original cart IDs can contain bearer capabilities, so Mango keeps a stable one-way digest of the exact string; it never logs cart tokens or recovery URLs.

Each pixel POST targets the primary storefront URL supplied by Shopify (including custom domains, so the account cookie has the correct origin) and goes through the Shopify app proxy with a SHA-256 body digest and event ID in the query. Mango verifies Shopify's canonical query HMAC, exact shop/path, timestamp, body digest and event ID. A persistent digest receipt rejects conflicting replays. Only Shopify's signed `logged_in_customer_id` can map to an already imported customer/contact; a body cannot claim another recipient. Anonymous or unavailable account context stays unlinked. Catalog links must match fresh imported products and variants. `cart_viewed` is an observed snapshot; `product_added_to_cart` is only a line observation and never replaces a cart snapshot. An observed permission withdrawal sends a signed proxy privacy control; Mango removes linked behavioral observations and guards against replaying observations at or before the withdrawal. If that client control is lost, delivery remains unproven rather than an exhaustive consent ledger. Pixel privacy permission is independent of Mango email/SMS consent.

The collector proves accepted observations and signed account context, not that a human actually viewed a page or that all events arrived. A shopper can submit their own signed-proxy requests. Client loss, sandbox restrictions and webhook delivery loss remain possible. Never infer did-not-browse, abandonment or full purchase absence from this log. The actual shop must qualify fetch/proxy/CORS behavior and logged-in/anonymous identity on each supported storefront surface, including checkout differences; unavailable identity must stay unlinked.

Owner-only live acceptance: authorize the app/shop, scopes/protected data, extension release, activation and subscriptions; configure actual server credentials; confirm a consented real product/cart event and customer mapping, a quiet healthy range, privacy withdrawal, replay and retention behavior. No live API call, release or deployment was performed by the implementation.
