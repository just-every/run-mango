# Hydration duplication diagnosis

The original date defect came from readiness/zone knowledge being consumed inside streamed app content. The old hydration hook used a never-notifying subscription; until that subtree committed, its post-hydration snapshot/effects could remain unobserved until an interaction. Date-3 moved publication into the document and replaced the Saved … placeholder without a click, but did so by updating ancestor React context above every streamed route.

A context publication changes all consumers, including page-level date-formatting hooks in still-hydrating routes. React can retain the original subtree hidden while rendering its updated copy. Hidden elements still match DOM locators. The task's initial reproduction observed two Insights subtrees and two complaints rows (one hidden, one visible); the supplied historical CI also reported duplicate compliance rows.

OperatorLayout additionally used `<Await fallback={null}>`. In pinned TanStack Router 1.170.41, Await supplies React.Suspense only for a truthy fallback, so null supplied no boundary. The resource promise could suspend the entire app shell into the root Outlet boundary. Adding an explicit boundary inside main eliminated overlap in a 30-load local probe and passed both journeys, the native go-live member and the entire 23-journey local suite. It was insufficient: exact-head Verify 42496937599 at 7dc67ff711dd148dc18e18b3c2d0d7f8d31b1a1c still failed with duplicate SPF rows at compliance-journey.ts:78 and duplicate Stripe sections at stripe-journey.ts:78. Actual logs were read once per failed job using gh run view --log-failed. No generated-view exemption applies to those failures.

The final correction removes the ancestor context update. A document-mounted producer publishes to a cached external store. useSyncExternalStore gives every server/first hydration render the same stable `{hydrated:false,timeZone:'UTC'}` snapshot. The document effect publishes browser knowledge once; only committed subscribers are notified. A later hydrated consumer observes the current client snapshot after its initial server-compatible render. Repeated publication of the same zone is idempotent, including Strict Mode effect replay. Same-tab changes publish directly; the document owns the cross-tab storage listener. The producer has no React state and returns its children unchanged, so zone publication does not re-render the ancestor route tree.

The explicit resource Suspense boundary remains, allowing the shell and resource content to commit independently. The document's publication position stays above streamed /app content; the formatter and existing date assertions remain intact. No timers, polling, locator filtering, duplicate-removal code or assertion weakening was introduced.

The corrected store passed 50 consecutive Insights document loads with maximum matching row count 1 and no two-copy overlap. The initial Node 22 date-3 reproduction had failed after six observed loads with maximum count 2. Zero console warnings/errors or pageerrors were captured in those diagnostic runs. The unchanged pre-send journey also passed its actual saved-date assertion after reload without a click; updated screenshots show `Saved 8 Nov 2026, 4:15 pm` at both widths. Full final-candidate suite and CI receipts are recorded separately; local success alone is not treated as final acceptance.
