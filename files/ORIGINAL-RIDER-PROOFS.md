# Original DONE-RIDERS proof column, verbatim from supplied reference

These are the existing 1-11 rider meanings; the scoped frozen rubric adds no checklist. CAMP-022 AP1-6 and the Requirement are copied verbatim in FROZEN-RUBRIC.md. Candidate exception and final guarded duties are exactly those in the commission.

| ID | Proof that satisfies it |
| --- | --- |
| R1 | One or a few named sanity journeys through the clause's public doors (route, command, browser, transport) perform each outcome the clause names and check what a user or the business would see, on the exact SHA with Verify green (DONE RULE, briefs/ct/judge-common.md, 28 Oct). The Status row's Evidence cell names each journey: its file in backticks, then its name. A journey may cover several clauses. A sentence without its own assertion, a surviving mutation, a missing unit or pin test, receipt form and Gap-cell wording are notes for the lander or ct, never a reason for STAYS PARTIAL. |
| R2 | The journey runs on real seeded data and checks the result a user or the business would see. A money, security or data-loss clause's journey executes the dangerous path both ways: the supported case is served and the unsafe case is refused and changes nothing. |
| R3 | The journey is invoked by push, pull_request or dispatch Verify and that run is green on the candidate SHA. An outside-Verify job counts only where the sentence names a clock or scale proof, with its receipt at the exact SHA. |
| R4 | Re-run on the candidate, or show with a diff that no byte of the relevant code or test changed since. |
| R5 | Cite the Base duty as `*Cites:* BASE-...` in the receiving clause's meta line and write only its delta, or name the duty in its own acceptance points; otherwise keep the duty in the Gap of the clause that owes it. |
| R6 | A done row has an empty Gap. A partial or missing row's Gap names what is missing and narrows no scope; Evidence names the proof present on the candidate; `node <parser dir>/contract-docs.mjs check` passes on the candidate; the `Judged from` line names the candidate commit. |
| R7 | An acceptance point changes only by a ct ruling recorded in the seed's RULINGS.md. State each CT rider once, as a door rule, a Base citation or the clause's own acceptance point. In a rewrite, `docs/contract/COVERAGE.json` stands in for keeping every original sentence verbatim, under the standard's coverage and status-carry rules. |
| R8 | The clause's journey runs the dangerous path both ways through the public door: the owner's correction or refund lands with its audit, archive and closed-period effect, and a non-owner, wrong-state or wrong-permission attempt is refused and changes nothing. One journey covers the clause's verbs; a test per verb is not required. |
| R9 | Keep the honest boundary named in the Gap; claim only what a real provider receipt or journey shows at the exact SHA. |
| R10 | Post an ASK with the default first; count nothing until the ruling, then synchronize its exact wording. |
| R11 | Main equals the SHA (ls-remote); exact-SHA Verify green (a canceled duplicate main-push Verify is not counted); Run site green on it; complete full-history publication scan NEW 0; diff against the prior main limited to the clause's status, Gap and counts plus the work. |
